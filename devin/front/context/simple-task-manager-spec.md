# Simple Task Manager 仕様書

## 1. 目的

本アプリは、Devinを利用した開発手順および成果物の品質を確認するためのテスト用Webアプリケーションである。

主な確認対象は以下のとおりとする。

- 仕様書を読み取り、要件に沿って実装できること
- 適切なプロジェクト構成を作成できること
- 基本的な画面操作を実装できること
- 入力チェックや例外ケースを考慮できること
- 単体テストを作成・実行できること
- READMEなどのドキュメントを作成できること
- Git上で適切にコミットし、Merge Requestを作成できること
- 実装したアプリを自ら操作して動作確認できること

---

## 2. アプリ概要

利用者が日々のタスクを登録、完了、削除できるシンプルなタスク管理アプリを作成する。

### 2.1 アプリ名

**Simple Task Manager**

### 2.2 想定利用者

個人利用者

### 2.3 利用環境

- PCのWebブラウザ
- Microsoft Edge
- Google Chrome

---

## 3. 技術要件

### 3.1 使用技術

| 区分 | 技術 |
|---|---|
| フロントエンド | React |
| 言語 | TypeScript |
| ビルドツール | Vite |
| スタイル | CSS |
| データ保存 | ブラウザのLocalStorage |
| 単体テスト | Vitest |
| UIテスト | React Testing Library |
| ソース管理 | Git |
| リポジトリ | GitLab |

### 3.2 技術上の制約

- バックエンドサーバーは使用しない
- データベースは使用しない
- 外部APIは使用しない
- 認証機能は実装しない
- 外部の有料サービスは使用しない
- 機密情報および実データは使用しない
- PC上で `npm install` および `npm run dev` により実行できること
- 本テストでは本番環境への公開を行わず、ローカル環境または自社のCI/CD環境で動作確認すること

## 4. 機能要件

### 4.1 タスク一覧表示

登録されているタスクを一覧表示する。

#### 表示項目

- 完了状態を示すチェックボックス
- タスク名
- 登録日時
- 削除ボタン

#### 表示順

登録日時の新しいタスクを上に表示する。

#### 初期表示

タスクが1件も登録されていない場合、以下のメッセージを表示する。

> タスクは登録されていません

### 4.2 タスク登録

入力欄にタスク名を入力し、「追加」ボタンを押すことでタスクを登録する。

#### 入力項目

| 項目 | 必須 | 制約 |
|---|---:|---|
| タスク名 | 必須 | 1文字以上、50文字以内 |

#### 登録時の処理

1. 入力内容を検証する
2. 問題がなければタスクを登録する
3. 一覧の先頭に追加する
4. 入力欄を空にする
5. LocalStorageに保存する

#### 入力チェック

- 空文字は登録できない
- 空白だけの文字列は登録できない
- 50文字を超える場合は登録できない
- 入力値の前後にある空白は削除する

#### エラーメッセージ

| 条件 | メッセージ |
|---|---|
| 未入力または空白のみ | タスク名を入力してください |
| 50文字超過 | タスク名は50文字以内で入力してください |

### 4.3 タスク完了

タスク左側のチェックボックスを選択すると、タスクを完了状態に変更する。

#### 完了状態の表示

- タスク名に取り消し線を表示する
- 文字色をグレーに変更する
- チェックボックスを再度選択すると未完了に戻る
- 状態変更後、LocalStorageに保存する

### 4.4 タスク削除

各タスクの「削除」ボタンを押すと、対象タスクを削除する。

#### 削除確認

削除前に確認ダイアログを表示する。

> このタスクを削除しますか？

#### 操作

- 「OK」の場合、タスクを削除する
- 「キャンセル」の場合、削除しない
- 削除後、LocalStorageの内容を更新する

### 4.5 絞り込み表示

以下のボタンにより、表示するタスクを切り替える。

| ボタン | 表示内容 |
|---|---|
| すべて | 全タスク |
| 未完了 | 未完了のタスクのみ |
| 完了済み | 完了済みのタスクのみ |

初期状態では「すべて」を選択する。

### 4.6 件数表示

画面上に次の件数を表示する。

- 全タスク件数
- 未完了件数
- 完了済み件数

表示例：

> 全5件、未完了3件、完了済み2件

### 4.7 データ保存

タスク情報をブラウザのLocalStorageに保存する。

#### 保存項目

```text
id
title
completed
createdAt
```

#### 保存要件

- ブラウザを再読み込みしても登録内容が保持されること
- 保存データが存在しない場合でもエラーにならないこと
- 不正な保存データを読み込んだ場合、アプリが停止しないこと
- 不正なデータの場合は空のタスク一覧として扱うこと

## 5. 画面仕様

### 5.1 画面構成

```text
+--------------------------------------------------+
| Simple Task Manager                              |
+--------------------------------------------------+
| [ タスク名を入力                          ] [追加] |
|                                                  |
| 全5件、未完了3件、完了済み2件                    |
|                                                  |
| [すべて] [未完了] [完了済み]                     |
|                                                  |
| [ ] 資料を作成する       2026/09/11  [削除]      |
| [x] 会議を設定する       2026/09/10  [削除]      |
| [ ] メールを送信する     2026/09/10  [削除]      |
+--------------------------------------------------+
```

### 5.2 デザイン要件

- シンプルで視認性の高いデザインとする
- 画面中央にコンテンツを配置する
- 最大横幅は800px程度とする
- ボタンの用途を色だけで区別しない
- キーボード操作ができること
- Enterキーでもタスクを登録できること
- 入力欄と各ボタンに適切なラベルを設定する
- 完了状態を色だけで表現せず、取り消し線も併用する
- スマートフォン幅でも大きくレイアウトが崩れないこと

---

## 6. 非機能要件

### 6.1 操作性

- 初めて利用する人でも説明なしで操作できること
- ボタン名から操作内容を判断できること
- エラー発生時に利用者が修正方法を判断できること

### 6.2 性能

- タスクが100件登録されていても、通常の画面操作に支障がないこと
- 初期表示が著しく遅延しないこと

### 6.3 保守性

- UI、型定義、データ操作を適切に分離すること
- 主要な処理を一つのコンポーネントに集中させないこと
- TypeScriptの `any` は原則使用しないこと
- 複雑な処理には簡潔なコメントを付けること
- 未使用のコードや依存ライブラリを残さないこと

### 6.4 セキュリティ

- タスク名をHTMLとして直接描画しないこと
- APIキー、パスワードなどの秘密情報を含めないこと
- `npm audit` を実行し、結果を報告すること
- 実データや社内情報をテストデータとして使用しないこと

## 7. テスト要件

### 7.1 自動テスト

最低限、以下のテストを作成する。

| No. | テスト内容 | 期待結果 |
|---:|---|---|
| 1 | 有効なタスク名を入力して追加する | タスクが一覧に表示される |
| 2 | 未入力で追加する | エラーメッセージが表示される |
| 3 | 空白だけを入力する | エラーメッセージが表示される |
| 4 | 51文字を入力する | エラーメッセージが表示される |
| 5 | タスクを完了にする | 完了状態の表示になる |
| 6 | 完了タスクを未完了に戻す | 未完了状態の表示になる |
| 7 | タスクを削除する | 対象タスクが一覧から消える |
| 8 | 削除をキャンセルする | 対象タスクが残る |
| 9 | 未完了で絞り込む | 未完了タスクのみ表示される |
| 10 | 完了済みで絞り込む | 完了タスクのみ表示される |
| 11 | データを保存する | LocalStorageに保存される |
| 12 | 保存データを読み込む | 再表示後もタスクが復元される |
| 13 | 不正な保存データを読み込む | アプリが停止せず空一覧になる |
| 14 | Enterキーを押す | タスクが登録される |
| 15 | 件数を表示する | 各状態の件数が正しい |

テストコードの作成だけでなく、テストの実行結果および失敗時の修正内容も報告すること。

### 7.2 ブラウザ動作確認

自動テスト完了後、ブラウザを使って以下を確認する。

1. タスクを3件登録する
2. 1件を完了状態にする
3. 「未完了」で絞り込む
4. 「完了済み」で絞り込む
5. タスクを1件削除する
6. ブラウザを再読み込みする
7. 登録内容が保持されていることを確認する
8. スマートフォン相当の画面幅で表示を確認する

可能な場合は、動作確認のスクリーンショットまたは録画を成果物として提示する。

## 11. Devinへの作業指示

添付の仕様書に従い、「Simple Task Manager」を実装すること。

### 11.1 作業手順

1. 仕様書を確認し、実装方針と作業計画を提示する
2. React、TypeScript、Viteでアプリケーションを実装する
3. タスクデータはLocalStorageに保存する
4. VitestとReact Testing Libraryで自動テストを作成する
5. 自動テスト、TypeScriptチェック、ビルド、`npm audit` を実行する
6. エラーが発生した場合は原因を特定して修正する
7. アプリをローカル起動し、ブラウザで主要な操作を確認する
8. セットアップ方法、起動方法、テスト方法を `README.md` に記載する
9. 変更をGitにコミットする
10. GitLabにMerge Requestを作成する

### 11.2 実装時の条件

- 仕様に不明点がある場合は、過度に機能を追加せず、合理的な前提を置いて進めること
- 仕様に記載のない外部サービスは使用しないこと
- TypeScriptの `any` は原則使用しないこと
- テストを通すためだけの不自然な実装は行わないこと
- 実データ、社内情報、認証情報を含めないこと
- 不要な依存ライブラリを追加しないこと
- タスク名はHTMLとして直接描画しないこと

### 11.3 完了時の報告事項

- 実装した機能
- 主要な設計判断
- 作成または変更したファイル
- 自動テストの件数と実行結果
- ビルド結果
- `npm audit` の結果
- ブラウザで確認した操作
- 未対応事項または既知の制約
- Merge RequestのURL
